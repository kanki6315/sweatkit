# M1–M3 device acceptance

Status: pending. Use this after the remaining implementation is ready; the current build does not yet support every step. Record build/commit, phone model, OS, date, pass/fail and observations. Simulator results do not certify device performance.

1. **Local library:** import an outdoor ride, indoor/Zwift ride, walk, corrupt FIT and truncated FIT from Files. Successful imports remain; rejected files explain why and add nothing. Import the successful files again: no duplicate activities. Relaunch and verify the same feed and detail values.
2. **Scale:** import 500 representative files, browse/filter/search during and after import, cancel a batch and retry. Record elapsed import time, scrolling stalls and memory pressure. Relaunch and confirm count and originals. Identical copies of one file do not count as 500 representative activities.
3. **Detail:** cold-open and cached-open a real five-hour ride. Record time until cached data is usable (target under one second). After imagery loads, scrub/zoom/pan/select while measuring (target 60 fps). Test no-GPS, indoor and unsupported-sport activities without invented data.
4. **Readability and accessibility:** use the existing 20-step timeline checklist and flyover checklist. Check dark casing over bright/dark satellite ground, light-mode cyan/yellow charts, maximum Dynamic Type, VoiceOver, Reduce Motion, Reduce Transparency and Increase Contrast. Check gesture conflicts in the actual detail screen.
5. **Profile:** set date-effective power thresholds and heart-rate values, correct one historical interval, and verify only affected activities recalculate. Test metric/imperial values and missing thresholds.
6. **Garmin account:** enter a Personal API key in Settings yourself. Test first backfill, pause/relaunch/resume, quick sync, old late uploads, deep scan and full reconciliation. Interrupt the network and retry. Verify expired/rejected key, renewed token failure and rate-limit recovery messages. Confirm source removals keep local data and show their status. Verify the expiry reminder from the user-entered expiry date.
7. **Apple Health:** grant read access yourself. Import a workout, then a delayed route/sample update. Relaunch and verify anchored progress. Revoke access, refresh, and follow recovery; do not interpret an empty result as proof of permission denial. Restore access and verify retry without loss or duplicates. Delete a source workout and confirm local retention plus status.
8. **Identity:** record the same activity in Garmin and Apple Health. Verify one activity with attribution, original-file primary and preserved alternatives. Switch primary; inspect the notice when an alternative has extra channels. Verify a partial recording is flagged, keep separate, then introduce a third matching recording. Separate a merged activity and check inherited title/visibility. Hide, refresh, restore, and verify it stays hidden until restored.
9. **Permanent deletion:** use only a designated disposable activity, read the confirmation, then verify its originals/snapshots/streams/results are erased and the retained tombstone prevents reimport. This check must wait for the deletion flow to be implemented.

Attach results to `M1-M3-ACCEPTANCE.md`. Unrun, blocked, or inconclusive checks stay open; do not infer a pass from package tests or a successful build.
